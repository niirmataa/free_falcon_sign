# Zasoby stopped region z initial blocks i resetami

JOINT daje conditional per reached root `E[T_j|F_j]<=24576`,
`Pr(T_j>49152|F_j)<2^-1024` i3072 scalar calls. Każda propozycja czyta
getters8,8,1,8,8 =33 returned bytes. Budget to ghost accounting, nie timeout
source lub nowa rejection branch.

Per root startptr0 następuje po JEDNYM initial block. Niech r_j oznacza
dodatkowe getter refills, D_j getter-discarded bytes, q_j finalptr.
Cała propozycja kończy się u64 read, zatem8<=q_j<=4094. Każdy u64 refill
przy ptr>=4087 porzuca<=9 bytes; u8 rollover porzuca0. Stąd:

```
33 T_j + D_j = 4096 r_j + q_j,  0<=D_j<=9r_j,
4087 r_j + 8 <= 33 T_j,
r_j <= floor((33T_j-8)/4087),
4096(1+r_j)=33T_j+D_j+(4096-q_j).
```

Na krawędzi re-init całe `4096-q_j` zostaje porzucone, nie dodane do
getter drops następnej próby. Dla J completed roots U_final=4096-q_J,
A_reinit=sum_(j<J)(4096-q_j). Sumowanie per-root equations daje:

`4096(J+sum r_j)=33T_region+D_getter+A_reinit+U_final`.

Zatem A_reinit<=4088(J-1), U_final<=4088; obie kategorie są osobne.
Ready cut nie ma bieżącego initial block. General reset/get_u8 control
kończący na rollover może porzucić4096, ale nie jest complete-proposal/root
endpointem; jego większy tail nie obala boundu4088 na tym domain.
