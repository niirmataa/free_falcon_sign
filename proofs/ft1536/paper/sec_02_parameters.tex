\subsection{Profile and family scope}
FT1536 is the degree-$1536$ ternary profile of the Falcon-derived code in
\code{Extra/c}. The pinned configuration enables
\code{TRUE_TERNARY_SECRET=1} and \code{TRUE_TERNARY_SECRET_MODE=1},
uses the emulated floating-point implementation, and fixes
\code{SIGN_MAX_ATTEMPTS=16}. Its modulus is $q=18433$ and its strict
quadratic-form threshold is $B=2093922385$. In the API the profile is
selected by \code{falcon_keygen_new(10, 1)}; the second argument selects
the ternary branch, so the first argument alone is not the logarithm of
the degree of a binary profile.\src{C02,C03}

\subsection{The three algorithms}
The scheme is presented as three boxes. They restate pinned interfaces
and add no statement of their own; each box is followed by its scope.

\begin{algorithm}[t]
\caption{FT1536 key generation (as pinned)}\label{alg:keygen}
\begin{algorithmic}[1]
\Require profile FT1536 ($n=1536$, $q=18433$), ternary-secret mode
\Ensure retained material $(f,g,F,G,h)$, or retry
\Repeat
  \State sample ternary $f,g$ of coefficient bound $1$
  \State run the NTRU solver; on success obtain $F,G$ of bound $2047$
    with $f\cdot G-g\cdot F=q$
  \State apply the recorded acceptance gates: resultant, norm,
    Gram--Schmidt, public-key invertibility, solve, leaf certificate
  \State run the fixed public computation on $f,g$ and obtain the
    canonical public polynomial $h=g\cdot f^{-1}$
\Until{the attempt succeeds or the configured cap ($3000000$) is reached}
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[t]
\caption{FT1536 signing (capped attempts)}\label{alg:sign}
\begin{algorithmic}[1]
\Require message $m$, secret material $(f,g,F,G)$; attempt cap $16$
\Ensure signature $s$, or failure
\State derive the challenge $c$ from $m$ and a fresh nonce
  ($40$-byte framing)
\For{$i=1$ to $16$}
  \State run one attempt on the fiber $A_h(u,v)=c$; a norm rejection
    yields $\none$
  \State on a positive emission, return the second vector $s$ if it is
    signed-$16$
\EndFor
\State return failure (cap exhausted)
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[t]
\caption{FT1536 coefficient-level verification}\label{alg:verify}
\begin{algorithmic}[1]
\Require public polynomial $h$, challenge $c$, candidate $s$
\Ensure accept or reject
\State \textbf{reject} unless $s$ is signed-$16$
\State \textbf{reject} unless
  $Q(\operatorname{center}(c-h\operatorname{reduce}(s)),s)<B$
\State \textbf{accept}
\end{algorithmic}
\end{algorithm}

\noindent Algorithm~\ref{alg:keygen} is a presentation of the pinned
KeyGen interfaces; its derivation status is the stage ledger of
Section~\ref{sec:b1status}: B1.05 is closed at scope, B1.06 Acceptance
is met, B1.07 is in progress, and none of these is a whole-KeyGen or
termination statement. Algorithm~\ref{alg:sign} is the probability-law
specification of Section~\ref{sec:reduction}; which attempt shape the
realized signer obeys is open. Algorithm~\ref{alg:verify} is exactly the
coefficient-level predicate of Section~\ref{sec:model}. Termination, the
emitted-key law and the byte-level framing sit outside these boxes
(Assumption~\ref{ass:a34}; Section~\ref{sec:limits}).\src{C02,C03,C05,C21}

\subsection{Acceptance is measured, not postulated}
The FG\_PROBE record uses deterministic synthetic seeds and the derived
profile's compiler flags, adding only the probe define. Its measurement
run records $8192$ successful keys in $23628$ attempts, with
$15436$ rejected attempts. The reported empirical acceptance rate is
$\widehat p_{\mathrm{accept}}=0.34671$ and the reciprocal is approximately
$2.884$. The largest observed attempt count per key is $24$; there are
no recorded hits of the configured KeyGen cap, $3000000$. These are
finite-run observations, not a rigorous acceptance lower bound or a
uniform-seed distribution theorem.\src{C02}

The source notes group acceptance into the resultant, norm,
Gram--Schmidt, public-key invertibility, NTRU-solve and mandatory leaf
certificate gates. The receipt has separate resultant counters for
$f$ and $g$: respectively $376$ and $392$ rejections, followed by
$0$ norm, $12303$ Gram--Schmidt, $814$ public-key and $1551$ solve
rejections. It does not give a separate leaf-certificate rejection
counter. A transparency control compared the clean and instrumented
builds on $256$ identical synthetic seeds and found identical recorded
key digests in all cases. This control supports the measurement procedure;
it does not prove observation-only instrumentation for all executions.
\src{C02}

\subsection{Encoding and the meaning of a fixed size}
The B3 model covers the FT1536 coefficient-vector encoding, including
the header, final zero-bit padding and exact consumption. Its STATIC
round-trip theorem requires $1536$ coefficients in the signed-$16$-bit
domain. The raw comp-0 round trip has the narrower domain
$[-9216,9216]$. STATIC refers to this codec and does not assert a fixed
signature length or constant-time execution. Encoder injectivity is
proved on the stated domains; decoder injectivity on all byte strings
is false, with formal aliases at zero and at $-32768$. These local
codec results do not discharge the global A3/A4 bridge.\src{C13}

For comparison, the separately pinned Falcon round-3 API defines a
PADDED format of $666$ bytes for Falcon-512. That API explicitly describes
padding and restarting generation until the signature fits the selected
size; it distinguishes PADDED from its CT format. Thus $666$ describes a
particular framing and retry policy, not the unconditioned length of
every compressed output. The FT1536 B3 analysis instead states the
codec domain and consumption requirements, and separately records the
caller's output-buffer failure path. This is the relevant comparison:
a byte-length headline does not specify the emitted probability law or
its failure behavior. No defect in Falcon is inferred from padding
itself.\src{C13}
