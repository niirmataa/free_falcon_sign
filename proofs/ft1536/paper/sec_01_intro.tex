\section{Introduction}\label{sec:intro}
The objective of the FT1536 development is a security argument whose
objects can be traced to a specified implementation. Such an argument
requires more than a reduction between ideal games: the key law,
sampler law, randomness interface and byte-level acceptance predicate
must refer to the same experiment. The present artifact contains a
conditional classical reduction and several source-bound components;
their final implementation-level composition is unfinished.\src{C01}

A reduction proved for an idealized scheme says little about a concrete
signer unless the sampler, the key law and the randomness interface of
the proof are the ones the code implements. Our own experience supports
the insistence: the source-binding process described in
Section~\ref{sec:binding} found defects not only in the vendored C code
but also in the formal models that were being built to describe that
code. A proof about a model is not a proof that the model describes the
source; keeping the two obligations separate is a design choice of this
work.\src{C11,C12}

The argument of this paper therefore runs in one direction only:
source execution, then the material and law that execution actually
produces, then the security experiment that material must feed, then
the reduction. Each link is a statement with its own premises; no link
is promoted to the next by naming convention. Where a link is missing
--- the honest-signing hop, the realized attempt shape, the emitted-key
law --- the text says so, and the missing link is a named obligation
rather than an implicit consequence of the closed parts.\src{C01,C21}

\subsection{Contributions}
\begin{enumerate}
\item A conditional classical reduction from EUF-CMA to the multi-target
inhomogeneous short-integer solution problem for the defined FT1536
game, with explicit source-instantiation obligations. The computed
sampler margins give $e=k^{32}-1<2^{-32}$ under the unconditioned
pointwise and shape premises; the acceptance-conditioned alternative
has $e<2^{-17}$ (Sections~\ref{sec:main}--\ref{sec:sampler}).
\src{C04,C06,C07,C08}
\item A source-binding method, from C99 fragments through an executed
statement tree to kernel-checked execution theorems, with explicit
kernel counterexamples to insufficient premises and concrete defects
found in both the C code and the formal models
(Section~\ref{sec:binding}).\src{C11,C12}
\item A two-level security declaration: model-dependent lattice
diagnostics and symmetric search ceilings reported side by side, with
the system accounting taken as their minimum rather than advertised
from the lattice exponent alone
(Section~\ref{sec:security}).\src{C14,C20}
\item Negative results as theorems: impossibility statements ruling out
whole-tail control from bulk comparisons, pointwise control from
total-mass sandwiches, the machine stage from additive accuracy alone,
and a statistical treatment of the modeled finite-state generator
(Section~\ref{sec:sampler}; Theorems~\ref{thm:bulkonly},
\ref{thm:mass}, \ref{thm:additive} and~\ref{thm:routea}).\src{C09,C10}
\end{enumerate}

FT1536 exists because trust in signature software should rest on
arguments that anyone can inspect, not on the authority of whoever
shipped the binary. The project develops ternary-secret signature
profiles in the Falcon lineage --- freely chosen, freely auditable,
freely usable --- to make independently inspectable cryptographic tools
available to people who wish to choose and evaluate such tools
themselves. That purpose requires publishing limitations and failed
arguments alongside successful proofs, binding claims to the exact code
that runs, and preserving the attribution of the Falcon Project and
Thomas Pornin. Accessibility is a design aim; it is not evidence for a
security claim.

\subsection{What is fixed, proved, and still being analyzed}\label{sec:fixed}
\paragraph{Fixed at this snapshot.}
The FT1536 profile, coefficient relation, capped reference signing law,
classical query interface and cited source bytes are explicit inputs.
The emitted-key law is a named object whose implementation binding
remains to be supplied. The hashes in Appendix~\ref{app:bindings}
identify the selected evidence; the profile name alone does not.
\src{C01,C02,C03,C05}

\paragraph{Proved at the stated interfaces.}
Theorem~\ref{thm:conditional} supplies the conditional reduction;
Theorem~\ref{thm:public} supplies the computational public-game bound.
The sampler transports and counterexamples of Section~\ref{sec:sampler}
are kernel results about their specified laws and premises. The
source-bound execution propositions of Section~\ref{sec:binding}
(Propositions~\ref{prop:ntru} and~\ref{prop:pubkey}) establish the
NTRU and public-key equations for the same material at their respective
fragment boundaries. Those propositions remain \NOTREVIEWED{} at stage
level; the enclosing invocation stage remains \INFLIGHT.
\src{C04,C06,C09,C15,C21}

\paragraph{Still being analyzed.}
The honest-signing hop, realized attempt weights and shape, and
emitted-key law must refer to the same source experiment. The global
A3/A4 byte bridge remains outside the proof. S06 lattice numbers are
\UNCERTIFIED{} diagnostics; the symmetric ceiling is not an achieved
security level. All reduction statements use classical oracle access.
Section~\ref{sec:limits} records these boundaries and the remaining
obligations; it makes no QROM claim.\src{C01,C08,C14,C18,C20}

\paragraph{Organization.}
The paper follows the classical order. Section~\ref{sec:model}
fixes notation and the threat model;
Section~\ref{sec:parameters} presents the FT scheme with its pinned
parameters and the three algorithm boxes. Section~\ref{sec:main}
states the end-to-end thesis as a target and the closed conditional
theorem; Section~\ref{sec:reduction} develops the classical reduction
in a form readable without the proof assistant;
Section~\ref{sec:sampler} computes the sampler margins and states the
negative results as theorems. Section~\ref{sec:binding} records the
source-binding method and its findings;
Section~\ref{sec:security} gives the two-level security accounting;
Section~\ref{sec:computational} details the computational seam.
Section~\ref{sec:related} is a declared literature stub, and
Section~\ref{sec:limits} closes with the honesty ledger and
conclusion. The appendices carry what the body deliberately does not:
Appendix~\ref{app:trust} binds every statement to its formal export,
batch record and pinned bytes and states how the appendices are
organized; Appendix~\ref{app:origin} reserves the project's provenance
record.\src{C01,C17}
