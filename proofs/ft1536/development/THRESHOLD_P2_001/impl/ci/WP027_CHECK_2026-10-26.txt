== Cel ==
Zamrozić format wire v1 (SPEC §9.2/§9.3/§9.5): kanoniczny CBOR dla
`body` i `envelope`, ścisły dekoder (non-canonical = odrzucone, nie
„naprawione”), MAC nad `canonical(envelope \ {3})`, `msg_id` nad
`canonical(body)`, schematy CDDL w repo i przypięte wektory.

== Co zrobiono ==
1. `crates/ft-threshold-protocol/src/cbor.rs` — ścisły podzbiór
   kanonicznego CBOR bez zależności zewnętrznych:
   - writer: uint/bstr/mapa wyłącznie najkrótszą formą (ai 24/25/26/27),
   - reader: odrzuca major 1/3/4/6/7, ai ≥ 28 (nieokreślone i
     zarezerwowane), formy nieskrócone, bstr ponad limit, śmieci po
     elemencie; `next_item_bytes` przegląda zagnieżdżenie z limitem
     głębokości (MAX_DEPTH = 8).
   - 7 testów jednostkowych, w tym wektory RFC 8949 Apendyks A dla uint
     (0, 23, 24, 255, 256, 65535, 65536, 2^32−1, 2^32, u64::MAX).
2. `envelope.rs` przełączony z przejściowego kodowania binarnego na
   kanoniczny CBOR (format v1, `WIRE_VERSION = 1`):
   - `Body::to_cbor` / `TryFrom<&[u8]>` (ścisłe),
   - `Envelope::to_bytes` / `TryFrom<&[u8]>` (ścisłe; osadzone body,
     recipient 16 B, mac 32 B),
   - MAC = HMAC-SHA256(K_mac, MAC_DOMAIN || canonical(envelope\{3}))
     — dokładnie SPEC §9.3 (wcześniej: body+recipient płasko),
   - msg_id bez zmiany struktury: SHAKE256(MSGID_DOMAIN || canonical(body)),
   - replay-window/round bez zmian logiki; testy WP-020 przechodzą bez
     modyfikacji (18 testów envelope).
3. `CoreError::NonCanonicalCbor` (core, non_exhaustive) — jeden jawny
   kod dla wszystkich naruszeń formy.
4. Niezależna referencja Python (`ci/wire/cbor_reference.py`; własna
   implementacja kanonicznego CBOR, SHAKE256, HMAC-SHA256) generuje
   wektor end-to-end + 10 wariantów non-canonical; runner
   `ci/wire/run_wire_vectors.sh` porównuje bajty z repo.
5. Schematy: `wire/schema/envelope.cddl` (FROZEN v1),
   `wire/schema/payloads_v0.cddl` (pola normatywne 24 typów; SIGN_OPEN
   DRAFT → WP-041 zgodnie z SPEC §9.4). Opis: `wire/README.md`.

== Pułapki (zachowane jawnie) ==
1. Najkrótsza forma ma PIĘĆ poziomów (direct < 24, potem 1/2/4/8 B):
   pierwszy szkic pomijał ai = 26, co dla 2^16..2^32 dawało 8 B
   (non-canonical). Wyłapane testem RFC (65 536 → 0x1A …) przed commitem.
2. Kanoniczność nie wynika z „kodu na oko”: dekoder egzekwuje value ≥
   minimum dla ai (np. `0x18 0x00` odrzucone), a referencja Python jest
   osobną implementacją — rozjazd widoczny jako różnica bajtów.
3. Szybki parser debugowy w Pythonie podwójnie liczył nagłówek bstr
   (j już zawierało n) — fałszywy alarm o złej kolejności kluczy;
   autorytetem jest test Rust + regeneracja bajtów.
4. Zmiana formatu zmienia bajty MAC: stare koperty z WP-020 są
   nieważne. To zamierzone zamrożenie v1, nie regresja (brak
   produkcyjnych danych w tym formacie; domeny bez zmian, wersja nowa).
